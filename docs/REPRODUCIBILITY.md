# Reproduction guide

## Scope and outputs

The checked-in configuration covers seven backbones, 83 dataset/horizon configurations and three independent training runs per configuration. All raw observations, checkpoints, fitted parameters and measured scores remain local. The current Git tree contains no reference results.

`scripts/reproduce.py prepare` creates an isolated workspace, restores four pinned public source trees and applies their measured source changes. Other required native source modules and configurations are included under `native_payload`. It rewrites the original server path prefix into this workspace before training or data extraction. The source repository is not modified by a reproduction run.

After `train`, the native checkpoint is reused by every calibration comparison. `evaluate` collects up to 100 native fitting batches/windows and at most 50,000 calibration coordinates, freezes all requested models, and then traverses the complete test iterator once. It uses the same native draws, targets and training-defined diagnostic state partition for every correction.

Outputs are under `WORKSPACE/reviewer_outputs/runs/TASK_ID/`:

| File | Meaning |
| --- | --- |
| `training.npz`, `validation.npz` | Locally regenerated fitting coordinates and validation origin provenance |
| `parameters.json`, `frozen.json` | Final FSPC parameters, fitting protocol, and pre-test freeze record |
| `results.json` | Complete-test Native, full FSPC, mean/shape arms and calibration comparisons |
| `test_reservoir.npz` | Paired retained test cohort, at most 50,000 coordinates |
| `retained_results.json` | Four-arm ablation, optional controls, factorial interaction, complete-fit costs and compiled parity |
| `compiled.npz`, `parity_probe.npz` | Complete deployment state and memory-layout-preserving reload probe |

Complete-test scores and retained-cohort scores have different evaluation populations. Do not combine them into one summary. All runtime outputs and model/data binaries are ignored by Git.

`run_final_fspc.py` and `aggregate_final_fspc.py` also preserve the original 249-task cost campaign, including its stricter historical-fit replay checks. That runner expects the calibration/parameter records generated by the preceding campaigns; the reviewer adapter can run directly from newly supplied data without those records.

## Fitting and random streams

Native training uses each task's recorded run index 1, 2 or 3. Forecast collection seeds are run index + 10000 for training, + 20000 for validation, and + 30000 for testing. Calibration-reservoir priorities use run index + 40000; historical target-threshold sampling uses + 50000; nested fitting-budget ordering uses + 60000; retained-test priorities use + 70000; shuffled assignments use + 80000 through + 80004. These streams match the original campaign implementation.

FSPC fits on the earlier two thirds of validation forecast origins and selects its mean blend on the final third, purging overlapping targets. Fewer than 128 coordinates in either block invokes the documented training-fit / validation-select fallback. After selection, the weight is frozen and templates/means are refitted on all calibration coordinates. No test target enters fitting or model selection.

NsDiff ETTh1 retains the native shared F/G initializers, trained locally with the supplied configurations. The corrected NsDiff ETTm1, ETTm2 and ExchangeRate tasks use horizon 192. The DeepSTUQ training path retains the combined author architecture, pretraining, 20 AWA epochs, ten snapshots, ten dropout passes, training-only normalization and validation temperature fit.

## Data

`fetch-data` downloads the ten existing **data-only** archive parts from the repository's v1.0.0 release (about 639 MB compressed / 3.2 GB extracted) and places them in the native loader layouts. It does not download the historical code-and-results archive. This includes ETT, Electricity, Exchange, ILI, Weather, Traffic, Solar and PEMS03/04/07/08 where configured. These are the benchmark files used by the experiment; the dataset owners retain their terms.

Datasets may also be placed manually in `WORKSPACE/payload/home/wyj/` using `configs/tasks.json` and the restored native loader configuration paths. Do not normalize files in advance: retain each backbone's original preprocessing and train/validation/test split.

## Aggregation

`summarize` creates full and retained raw/configuration/backbone CSVs. A configuration contributes to three-run summaries only after all three configured runs finish. Configuration SD is the sample SD (denominator two). Backbone scores first average configurations within each run, then compute mean/sample SD across the three run averages. RMSE is computed from each run's MSE before averaging. Native-normalized factorial ratios are emitted after all seven backbones are represented. Original absolute traffic units are retained for DeepSTUQ, so cross-backbone comparisons use paired dimensionless ratios.

## Validation and scientific scope

The code-only refresh was checked by restoring all four public source trees in a fresh directory and running numerical tests of the final method and reviewer adapter. Tests do not require historical results. All seven native import probes and a real PPM/ETTh1/H192 complete-test pilot also passed (2689 windows, 3,614,016 coordinates, paired 50,000-coordinate controls and exact compiled checks), using an existing checkpoint. A new 249-run neural training campaign is not part of this code refresh.

The manuscript also incorporates author-supplied corrections to selected complete-test aggregate scores. Their corresponding prediction arrays are not included here. The reproduction code calculates every metric from generated predictions; it does not overwrite computed values with those aggregates. Exact compilation claims concern application of the same frozen FSPC model, separately from the variability of fresh neural training or a numerically nonunique blend optimizer.
